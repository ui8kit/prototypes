# Kit install

`packages/kit/src` is the UI8Kit Svelte primitive tree. Files are generated by
`@ui8kit/codegen` (`<!-- Code generated by @ui8kit/codegen. DO NOT EDIT. -->`)
and installed by the official CLI. Do not edit them.

## Official path

```sh
bun run kit:install
# → npx --yes ui8kit@3 init --yes --framework svelte --dir packages/kit/src
# → npx --yes ui8kit@3 add --all --force --retry
# → npx --yes ui8kit@3 check
```

That is `scripts/install-kit.sh`. It does **not** copy GitHub JSON, scrape the
registry repo, or rewrite primitive sources.

`ui8kit.config.json` points the CLI at `packages/kit/src`. `ui8kit.lock.json`
pins sha256 of every installed path (registry 3.4.0 / CLI 3.5.0).

## CDN fallback (CLI still)

The CLI loads `@ui8kit/registry` from npm via CDN, in order **unpkg → jsDelivr**:

- `https://unpkg.com/@ui8kit/registry@3/r/svelte/index.json`
- `https://cdn.jsdelivr.net/npm/@ui8kit/registry@3/r/svelte/index.json`

If npm or one CDN is down, retry with the same CLI:

```sh
npx --yes ui8kit@3 add --all --force --retry
npx --yes ui8kit@3 add --all --force --retry \
  --registry-url https://unpkg.com/@ui8kit/registry@3
npx --yes ui8kit@3 add --all --force --retry --strict-cdn \
  --registry-url https://cdn.jsdelivr.net/npm/@ui8kit/registry@3
npx --yes ui8kit@3 add --all --force --registry-version 3.4.0
```

CI does not run `kit:install`. GitHub Actions has npm; it installs
devDependencies (`bun install`) and uses the committed kit tree.

## What used to bypass the CLI

`scripts/install-kit.py` tried `npx ui8kit@3` and, on failure, copied
`github.com/ui8kit/registry` item JSON through `gh api`. Those JSON payloads
are the same packed files the CLI fetches from CDN, so the committed tree is
registry 3.4.0 primitives, not hand-written components. The Python bypass is
gone; reinstall is CLI-only.

## ui8px policy for the generated wireframes

`scripts/ui8px-extract.py` lints, next to `classes.ts`, the generated wireframes and shapes
(`packages/blocks/src/generated/svelte/{blocks,shapes}`) under the layout scope. They are rectangles on the kit `Box`
with plain layout classes: no composition, no recipe, no state or effect class ships with them (codegen-x
`packages/prototypes`), so there is no `controls` scope and no recipe file to lint.

The only allowlist entry (`.ui8px/policy/allowed.json`) the generated code adds to the bootstrap policy:

| Utility | Why |
| --- | --- |
| `aspect-3/4` | the portrait ratio of the media shape, next to the already allowed `aspect-square`, `aspect-video`, `aspect-4/3` and `aspect-21/9` |

Spacing stays the bootstrap scale (layout `0 2 4 6 8 10 12 16 20 24 32 40`: 32 and 40 are the `lg:` step of the section
padding presets).

## The catalog bundle (no tailwind-merge)

`bun run build:catalog` (`scripts/catalog-size.mjs`, also part of `bun run build`) builds
`packages/blocks/catalog/dist/catalog.{js,css}`: the generated wireframes, their contracts and models, the per-element
tokens, for embedding in constructors and admin panels. Its one difference from the app build: the kit's
`utils/cn.ts` (clsx + tailwind-merge, as `ui8kit add` installs it) resolves to `packages/blocks/catalog/kit-cn.ts`, the
`cn` that ui8kit/codegen emits with `generate --runtimes svelte --cn join` (a dependency-free join, no conflict
resolution). It is pinned in `codegen.lock.json` `kitCn` (codegen commit, generate flags, sha256) and synced/checked by
`scripts/sync-codegen.ts` (`--update-kit-cn <ref>`). `packages/kit` is never edited and the registry is unchanged; the app
build keeps the kit's merging `cn` (its chrome overrides recipe classes).

Same DOM: `catalog/wireframes.snap.html` holds every block × variant × padding preset; `src/manifest/wireframe-dom.test.ts`
renders it with the kit cn, `catalog/cn.test.ts` with kit-cn.ts, both must match. `catalog-size.mjs` fails if the bundle
pulls tailwind-merge or the kit's `utils/cn.ts` (clsx stays: the Svelte runtime uses it itself).
