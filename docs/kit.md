# Kit install

`packages/kit/src` is the UI8Kit Svelte primitive tree. Files are generated by
`@ui8kit/codegen` (`<!-- Code generated by @ui8kit/codegen. DO NOT EDIT. -->`)
and installed by the official CLI. Do not edit them.

## Official path

```sh
bun run kit:install
# → npx --yes ui8kit@3 init --yes --framework svelte --dir packages/kit/src
# → npx --yes ui8kit@3 add --all --force --retry
# → npx --yes ui8kit@3 check
```

That is `scripts/install-kit.sh`. It does **not** copy GitHub JSON, scrape the
registry repo, or rewrite primitive sources.

`ui8kit.config.json` points the CLI at `packages/kit/src`. `ui8kit.lock.json`
pins sha256 of every installed path (registry 3.4.0 / CLI 3.5.0).

## CDN fallback (CLI still)

The CLI loads `@ui8kit/registry` from npm via CDN, in order **unpkg → jsDelivr**:

- `https://unpkg.com/@ui8kit/registry@3/r/svelte/index.json`
- `https://cdn.jsdelivr.net/npm/@ui8kit/registry@3/r/svelte/index.json`

If npm or one CDN is down, retry with the same CLI:

```sh
npx --yes ui8kit@3 add --all --force --retry
npx --yes ui8kit@3 add --all --force --retry \
  --registry-url https://unpkg.com/@ui8kit/registry@3
npx --yes ui8kit@3 add --all --force --retry --strict-cdn \
  --registry-url https://cdn.jsdelivr.net/npm/@ui8kit/registry@3
npx --yes ui8kit@3 add --all --force --registry-version 3.4.0
```

CI does not run `kit:install`. GitHub Actions has npm; it installs
devDependencies (`bun install`) and uses the committed kit tree.

## What used to bypass the CLI

`scripts/install-kit.py` tried `npx ui8kit@3` and, on failure, copied
`github.com/ui8kit/registry` item JSON through `gh api`. Those JSON payloads
are the same packed files the CLI fetches from CDN, so the committed tree is
registry 3.4.0 primitives, not hand-written components. The Python bypass is
gone; reinstall is CLI-only.
